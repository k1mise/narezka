# narez — ссылка → вертикальные клипы (этап 1)

Работает: скачивание (yt-dlp) → речь в текст (faster-whisper) → выбор моментов локальной LLM (Ollama) →
нарезка 30–60 с в 9:16 → субтитры (опц. перевод) → рекламный баннер → группы аккаунтов в SQLite.
Публикация на площадки — этап 2 (сейчас dry-run).

## Установка (Windows)
1. Python 3.11+ (галочка «Add to PATH»)
2. `winget install Gyan.FFmpeg` — перезапусти терминал
3. Ollama: https://ollama.com → `ollama pull qwen2.5:7b` (слабый ПК: `qwen2.5:3b`, поменяй в config.toml)
4. В папке проекта:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

## Запуск
- Веб-версия (основная): двойной клик по `start.bat` (или `python run.py`) — поднимется http://localhost:8000 и откроется браузер. Вкладки: Панель, Редактор, Аккаунты, История; работает и на телефоне (в той же сети пока не открыт — только localhost). При первом запуске `start.bat` сам доставит fastapi/uvicorn.
- Старый GUI (пока оставлен): `python app.py` — создай группу → вставь ссылку → «Нарезать»
- CLI: `python -m narez.cli "https://youtube.com/watch?v=..." --group Собаки`
- Тесты: `pytest`

Клипы лежат в `workspace/clips/jobN/`. Все настройки (модель, длительность, баннер, язык субтитров) — `config.toml`.

## Баннер
`banner.enabled = true`, положи PNG в `assets/banner.png`. Появляется ровно на `start_at`…`start_at+duration`
секунд, не более `max_per_clip` раз.

## Структура
`downloader` → `transcriber` → `moments` (LLM + проверка длительности/границ по фразам) → `subtitles` →
`editor` (ffmpeg) → `pipeline`; `db` (группы/аккаунты/клипы); `publishers/` (заготовка этапа 2).

## Точность субтитров
- Слабая модель Whisper путает сленг и названия. `base` — для быстрых проверок, для результата ставь `small`
  (CPU) или `medium` / `large-v3` (видеокарта NVIDIA).
- `vocabulary` в `[whisper]` — впиши термины и имена из видео; название ролика подставляется автоматически.
- Видеокарта NVIDIA: `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` — программа сама подхватит библиотеки.
  Если не заработает, она сама перейдёт на процессор.
- У каждой модели свой кэш транскрипта, при смене модели видео распознаётся заново.

## YouTube Shorts (публикация)
1. https://console.cloud.google.com → создай проект → «APIs & Services» → включи **YouTube Data API v3**.
2. «OAuth consent screen»: тип External, добавь свой Google-аккаунт в **Test users**.
3. «Credentials» → Create credentials → **OAuth client ID** → тип **Desktop app** → скачай JSON, сохрани как `assets/client_secret.json`.
4. В программе: привяжи к группе аккаунт `youtube` → «Войти в YouTube» → в браузере выбери свой Google-аккаунт и канал.
5. Нажми «Опубликовать». По умолчанию `privacy = "private"` — проверь ролик на канале, потом поставь `public` в `config.toml`.

Задержка: 1-й клип уходит сразу, остальные — отложенно (`delay_minutes` в `[youtube]`), расписание хранит сам YouTube.
Важно: пока Google-проект не прошёл аудит API, YouTube может принудительно оставлять загруженные через API видео
приватными. Чтобы снять ограничение, подай форму аудита: https://support.google.com/youtube/contact/yt_api_form
Квота API: одна загрузка стоит ~1600 из 10 000 единиц в сутки (около 6 видео/день на проект).
Для нескольких каналов в разных группах используй одни и те же OAuth-данные — токен хранится на каждый аккаунт отдельно.

## Редактирование клипов, баннеры, история

- После нарезки клипы остаются в списке «Клипы, ждущие публикации» (список сохраняется между запусками). Двойной клик — окно
  редактирования: название, описание, хэштеги, баннер. «Открыть клип в плеере» — посмотреть клип, «Предпросмотр с баннером» —
  собрать клип с баннером и открыть.
- Баннер — PNG/JPG или видео (mp4/mov/webm). У видео-баннера свой звук: пока он идёт, звук основного видео приглушается до
  `duck_percent` (по умолчанию 15%) и плавно возвращается. Видео-баннер занимает не меньше `min_area_percent` (25%) площади экрана: сначала он увеличивается пропорционально (до ширины кадра), а если очень вытянутому баннеру этого мало — растягивается по высоте непропорционально, но не выше кадра.
  Баннер накладывается отдельным проходом ffmpeg при предпросмотре или публикации, поэтому его можно менять сколько угодно.
  Баннер по умолчанию для всех новых клипов задаётся в `[banner]` в config.toml (`enabled = true`).
- Вкладка «История»: превью (клик — открыть видео на YouTube), название, аккаунт, статус, просмотры/лайки/комментарии.
  «Обновить статистику» делает один запрос `videos.list` (1 единица квоты на 50 видео). Для статистики нужен доступ на чтение:
  один раз нажми «Войти в YouTube» заново (старые токены продолжают работать для загрузки).
- После успешной загрузки клипа во все аккаунты YouTube группы его файлы удаляются; исходное видео и кэш распознавания — когда
  в задании не осталось клипов в очереди (`[cleanup] enabled = false` отключает). Если канал упёрся в дневной лимит загрузок
  (`uploadLimitExceeded`), оставшиеся клипы просто ждут в очереди — нажми «Опубликовать» позже.

## Время публикации и публикация из редактора

- В окне редактирования у клипа есть поле «Время публикации» (формат `07.10.2026 18:30`, время вашего ПК). Кнопка
  «Запланировать на указанное время» загружает клип сразу, а на YouTube он выходит в назначенное время (минимум через 5 минут).
  Кнопка «Опубликовать сейчас» очищает время и выкладывает клип немедленно.
- Время клипа главнее общей задержки `delay_minutes`: клипы без своего времени идут по обычному правилу (первый сразу,
  следующие с задержкой). Если заданное время уже прошло, клип выкладывается сразу.
- Внимание: запланированное видео в назначенное время становится ПУБЛИЧНЫМ независимо от `privacy` в config.toml.
- На главной вкладке: «Опубликовать выбранный клип…» публикует только выделенный клип, «Опубликовать все клипы из списка» — все.


## Этап 2: что добавлено
- **Любые ссылки**: YouTube и ~1000 сайтов, прямые ссылки на файл (.mp4 и т. п.), страницы с плеером, ссылка без `https://`, плейлист (берётся первое видео), путь к видеофайлу на компьютере. Для сайтов, требующих вход: `[download] cookies_from_browser = "chrome"` в config.toml.
- **Папки** (Панель → «Видео из папок»): Исходники / Клипы / Тесты. Исходник → «Нарезать», готовый клип → «В редактор». Пути: `[paths] sources_dir / clips_dir / test_dir` (по умолчанию внутри `workspace`). Автоочистка после публикации удаляет файлы только внутри `workspace`.
- **Тестовый прогон** (галочка на Панели): клипы сохраняются в папку тестов, в редакторе помечены «тест», публикация для них отключена, автоочистка их не трогает.
- **Публикация выбранных клипов**: на «Панели» отметь клипы галочками (или «Выбрать все» / «Выбрать клипы всех групп») и нажми «Опубликовать выбранные» («Опубликовать все» открывает то же окно). В окне видно: порядок выхода (меняется стрелками ▲▼, лишнее убирается ✕), длительность, есть ли баннер, группа и её платформы, точное время выхода каждого клипа. Внизу — промежуток между выходами (быстрые кнопки или своё значение, не меньше 5 минут; «Все сразу» — без промежутка) и время выхода первого клипа («сразу» или конкретное время). Каждый клип уходит на все аккаунты своей группы.
- **Смена группы в редакторе**: при выборе другой группы программа спрашивает, перенести только этот клип или все клипы прежней группы.
- **Журнал задач**: на «Панели» внизу — список прошлых задач (нарезка, публикации). Нажми на задачу — откроется полный лог: какой клип на какой аккаунт ушёл, какие были ошибки и итог («загружено / ошибок / осталось в очереди»). Логи пишутся на диск в `workspace/logs` и не пропадают при перезапуске или обновлении страницы; хранятся последние 60 задач. Публикация с ошибками или лимитом канала остаётся на экране, пока не нажмёшь «Скрыть».\n- **Пресеты** (Редактор): баннер с настройками + теги + текст в конце описания; применить к одному клипу или ко всем клипам группы.
- **Видео-баннер с зелёным фоном (хромакей)**: если по углам видео однотонный зелёный фон, программа находит его цвет сама и включает галочку «Убрать однотонный фон». Фон становится прозрачным (с удалением зелёной каймы), пустые поля по краям обрезаются, а видимая часть растягивается так, чтобы занимать не меньше `min_area_percent` (25%) экрана, но не выходя за кадр. Цвет можно поправить вручную; параметры — `[banner] chroma_auto`, `chroma_similarity`, `chroma_blend`. В живом предпросмотре вырезание приблизительное — точный результат даёт «Точный предпросмотр».
- **Несколько баннеров**: в редакторе выбери первый баннер — под ним появится кнопка «+ Добавить ещё один баннер», она открывает новую карточку с отдельными настройками (файл, начало, длительность, ширина, положение, пауза). Лимит — `[banner] max_banners` (по умолчанию 5). Баннеры накладываются по порядку появления; если у раннего включена пауза, последующие сдвигаются на её длину. Пресеты хранят все баннеры.
- **Начало баннера**: «В секундах» от начала клипа или «В % видео» (например, 50% у клипа в 40 с = 20-я секунда).
- **Пауза на баннере**: галочка в настройках баннера (или `[banner] pause = true`). Основное видео замирает на кадре, играет баннер (со своим звуком), затем клип продолжается; клип длиннее на время баннера.
- **Прокси** (вкладка): список в любом формате (`ip:port`, `user:pass@ip:port`, `ip:port:user:pass`, `socks5://…`), проверка с показом IP, страны, города и пинга, выбор рабочего прокси. Используется только для скачивания видео; для SOCKS нужен пакет PySocks (есть в requirements).

## Вырезание рекламы из исходника

Перед нарезкой narez может вырезать из скачанного видео рекламные вставки. На панели «Новое видео» две галочки:

- **Вырезать рекламу по тексту (локальная модель)** — основной слой для русскоязычных видео. В транскрипте ищутся рекламные маркеры
  («промокод», «ссылка в описании», «скидка», «спонсор», «при поддержке»…), вокруг подозрительных мест Ollama определяет, где вставка
  начинается и заканчивается, а границы подгоняются под паузы в речи. Если модель недоступна, этот слой ничего не режет.
- **Вырезать рекламу по SponsorBlock (только YouTube)** — готовая разметка от зрителей (sponsor.ajay.app, запрос идёт по префиксу
  хэша ID, без прокси). Для свежих и русскоязычных видео разметки часто нет — тогда в логе будет «разметки нет».

Результат — файл `<название>.noads.mp4` в папке «Исходники» (одно перекодирование), транскрипт пересчитывается под него; клипы
берутся уже из видео без рекламы. После публикации файл удаляется вместе с исходником. Каждая вырезанная вставка пишется в журнал
задачи с таймкодом и цитатой — по ним видно, что именно вырезано.

Предохранители: вставка по тексту должна содержать рекламные маркеры, быть длиной 6–240 с; если «рекламой» оказалось больше 30% видео,
не режется ничего. Настройки по умолчанию менять не обязательно; при желании в `config.toml`:

```toml
[adcut]
sponsorblock = true                      # состояние галочек по умолчанию
text = true
sb_categories = ["sponsor", "selfpromo"] # ещё: "interaction", "intro", "outro", "preview"
min_seconds = 6                          # текстовый слой: минимальная/максимальная длина вставки, с
max_seconds = 240
max_share = 0.3                          # больше этой доли видео вырезать не будем
context_seconds = 45                     # сколько контекста модель видит вокруг подозрительного места
```

Модель оценивает только места с маркерами, поэтому реклама без слов (только картинка) и интеграции, спрятанные в обычный разговор, не находятся.

## Instagram Reels и TikTok

Оба сервиса публикуются через официальные API. Отложенной публикации у них нет, поэтому если у клипа задано время или
задержка, он попадает в **очередь** (страница «История» → «Очередь Instagram и TikTok») и выкладывается автоматически
в назначенное время — **пока narez запущен**. Клипы без времени уходят сразу.

Ключи приложений кладутся в файл `.env` рядом с `run.py` (шаблон — `.env.example`), в `config.toml` их хранить не нужно.

### Instagram (Instagram API with Facebook Login)
1. Аккаунт Instagram должен быть **профессиональным** (Business или Creator) и привязан к Facebook-странице.
2. https://developers.facebook.com → «Мои приложения» → создать приложение (тип Business) → добавить продукт **Instagram**
   (API setup with Facebook login) и **Facebook Login**.
3. Настройки приложения → Основное: скопируй **ID приложения** и **Секрет** в `.env` (`INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`).
4. Facebook Login → Настройки → **Valid OAuth Redirect URIs**: `http://localhost:8765/callback`
   (порт меняется в `config.toml`: `[instagram] redirect_port`).
5. Пока приложение в режиме разработки, публиковать могут только пользователи с ролью в приложении (Роли → добавь себя и
   владельцев аккаунтов администраторами/тестировщиками) — проверка Meta для этого не нужна. Чужие аккаунты — только после App Review
   прав `instagram_content_publish`, `instagram_basic`, `pages_show_list`, `pages_read_engagement`.
6. В narez: аккаунты → Instagram → «Войти» → разреши доступ к странице и Instagram-аккаунту.
Лимит API — 100 публикаций за 24 часа на аккаунт. Видео: Reels до 90 секунд, вертикальное.

### TikTok (Content Posting API)
**Режим по умолчанию — «черновики» (`mode = "inbox"`)**: narez загружает клип в черновики приложения TikTok (права `video.upload`),
а публикуешь его ты сам: в приложении TikTok (уведомление «Видео готово к редактированию») либо, чтобы отложить, — в TikTok Studio
(веб, нужен аккаунт Creator/Business, до 10 дней вперёд). API черновиков не принимает подпись, обложку и настройки — их задаёшь
при публикации; название и описание клипа сохраняются в истории narez. В истории такие клипы помечены «В черновиках TikTok».
Режим прямой публикации: `[tiktok] mode = "direct"` (требует аудита приложения TikTok).

1. https://developers.tiktok.com → Manage apps → создать приложение; добавить продукты **Login Kit** и **Content Posting API**
   (для режима direct включи Direct Post), права `user.info.basic`, `video.upload` (и `video.publish` для direct).
2. **Redirect URI**: `http://localhost:8766/callback/` (порт — `[tiktok] redirect_port` в `config.toml`).
3. **Client key** и **Client secret** → `.env` (`TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`).
4. Пока приложение не прошло аудит TikTok, все видео публикуются только как «Только я» (SELF_ONLY), а аккаунт должен быть
   добавлен в Sandbox/Target users. После аудита поставь в `config.toml` `[tiktok] privacy = "PUBLIC_TO_EVERYONE"` (это значение по умолчанию —
   если аккаунту разрешено только SELF_ONLY, narez выберет его сам).
5. В narez: аккаунты → TikTok → «Войти».

Дополнительные необязательные настройки в `config.toml` (добавлять нужно только то, что хочешь менять):

```toml
[instagram]
graph_version = "v23.0"
redirect_port = 8765

[tiktok]
mode = "inbox"                   # inbox — в черновики TikTok (по умолчанию) / direct — сразу в ленту (нужен аудит)
privacy = "PUBLIC_TO_EVERYONE"   # PUBLIC_TO_EVERYONE / MUTUAL_FOLLOW_FRIENDS / FOLLOWER_OF_CREATOR / SELF_ONLY
redirect_port = 8766
disable_comment = false
disable_duet = false
disable_stitch = false
```

## Ключи YouTube (Client ID и Client secret)

Вместо файла `client_secret.json` можно вписать ключи Google OAuth-приложения (Google Cloud → APIs & Services → Credentials →
Create credentials → OAuth client ID, тип **Desktop app**; включи YouTube Data API v3):

- **Для одного аккаунта:** Аккаунты → у нужного YouTube-аккаунта кнопка **«Ключи»** → вставь Client ID и Client secret → «Войти».
  У каждого канала могут быть свои ключи (например, из разных проектов Google Cloud) — тогда у каждого свой дневной лимит загрузок.
- **Для всех сразу:** `YOUTUBE_CLIENT_ID` и `YOUTUBE_CLIENT_SECRET` в файле `.env`.
- Если не задано ни то ни другое, используется `assets/client_secret.json`.

Порядок выбора: ключи аккаунта → `.env` → `client_secret.json`. Ключи аккаунта хранятся в `narez.db` (в Git не попадает).
Если при входе пишет «Access blocked / access_denied» — добавь почту аккаунта в «Test users» на экране OAuth consent screen
или переведи приложение в «In production» (в режиме тестирования вход живёт 7 дней).

### Если вход в YouTube не получается

Client ID и Client secret только говорят Google, *какое приложение* просит доступ. Сам канал всё равно нужно один раз разрешить
кнопкой «Войти» — после этого токен обновляется сам, повторно входить не нужно (кроме режима «Тестирование», где токен живёт 7 дней).

| Что пишет Google | Причина | Что сделать |
|---|---|---|
| `redirect_uri_mismatch` | ключи созданы как «Web application» | в Google Cloud создай **новый OAuth client ID типа «Desktop app»** и впиши его ключи |
| `access_denied` / «Access blocked… not completed verification» | приложение в режиме «Тестирование», почты нет в списке | OAuth consent screen → Test users → добавь почту аккаунта (или Publish app) |
| `invalid_client` | неверный Client ID или Client secret | скопируй заново, без пробелов |
| «Google Cloud access blocked… 2-step verification» | на аккаунте-владельце проекта выключена 2FA | включи двухэтапную аутентификацию |
| `quotaExceeded` / `uploadLimitExceeded` | дневной лимит API или загрузок канала | подожди сутки; у каждого канала может быть свой проект и свои ключи |
| вход «слетает» раз в неделю | приложение в режиме «Тестирование» | Publish app → In production |

Какой Google-аккаунт выбран на странице входа — не важно для этих ошибок: они зависят от приложения (проекта Google Cloud), а не от канала.

## Удержание зрителей (YouTube)

В истории есть колонка «Удержание» — средний процент ролика, который досматривают зрители (в карточке ещё и среднее время просмотра), и сортировка «По удержанию». Нужно:

1. В Google Cloud (тот же проект, что для загрузки) включить **YouTube Analytics API** и добавить в экран согласия доступ `yt-analytics.readonly`.
2. Один раз выйти и заново войти в каждый YouTube-аккаунт программы (кнопки «Выйти» → «Войти в YouTube»), подтвердив доступ к аналитике.

YouTube отдаёт эти данные с задержкой около суток, у свежих видео будет «—». Если доступа нет, статистика обновляется как обычно, а в журнале появится строка «Удержание зрителей пропущено».

## Видео-вставки (удовлетворяющие ролики под/над клипом)

Перед публикацией к клипу можно добавить случайное видео из папки `assets/fillers` (чистка ковров, песок, чернила и т. п.).

1. Скачай бесплатные ролики одной командой из папки narez: `python get_fillers.py` (Mixkit, свободная лицензия, 14 роликов). Можно добавить свои во вкладке «Вставки» или просто положить файлы в папку.
2. Выбери расположение: в «Редакторе» (карточка «Видео-вставка», для одного клипа) или в окне публикации (для всей пачки). Само видео выбирается случайно — или укажи конкретное в редакторе.
3. Раскладка кадра 1080×1920: клип (собирается прямо из исходного видео, на всю ширину полосы, без размытых полей, вместе с субтитрами) занимает ~52% высоты и прижимается к верху (вставка снизу) или к низу (вставка сверху). Если исходника уже нет, берётся кадр из готового клипа. Баннеры накладываются поверх готового кадра со вставкой. Обрезка по бокам сейчас по центру; для клипов, нарезанных до этого обновления, используется резервный вариант из готового клипа. Вставка занимает ~85% оставшегося места по высоте и 100% по ширине. Узкая полоска остаётся под название клипа: при «вставке снизу» она между клипом и вставкой, при «вставке сверху» — в самом верху.
4. Проценты можно поменять в config.toml (новые ключи необязательны):
```
[filler]
dir = "assets/fillers"
main_percent = 52          # какую часть высоты занимает клип
video_percent = 85         # какую часть оставшегося места занимает вставка
band_center_percent = 57   # откуда брать полосу из клипа (чтобы в кадре оставались субтитры)
strip_color = "#000000"    # цвет полоски названия
```
Вставка накладывается при публикации после баннера; звук остаётся от клипа. «Точный предпросмотр» в редакторе собирает готовый файл.

## Субтитры YouTube вместо Whisper

При скачивании ссылки с YouTube программа забирает и субтитры видео. Ручные субтитры (на языке звука) берутся всегда, когда они есть, — распознавание речи пропускается, это ускоряет обработку. Если ручных нет, выбор в панели «Нарезка»:
- «автоматические YouTube (быстро)» — по умолчанию; у них нет знаков препинания, поэтому предложения режутся по паузам;
- «распознать речь Whisper (точнее, дольше)» — как раньше.

Если у видео русский дубляж, берутся русские субтитры, иначе — язык оригинала. Для файлов с компьютера и не-YouTube источников всегда работает Whisper. Субтитры лежат рядом с видео (`*.captions.json`) и подхватываются при повторной нарезке из папки «Исходники».

## Ручная выкладка в TikTok

1. На «Панели» вставь ссылку и отметь **«Для ручной выкладки в TikTok»** — клипы нарежутся как обычно, но **без баннера** и попадут не в группу, а во вкладку **TikTok**.
2. Во вкладке у каждого клипа: плеер, название, описание, теги и кнопка **«Скопировать всё»**: в буфер по очереди записываются путь к файлу, описание и название (в истории буфера Windows, `Win+V`, лежат все три; последним — название). Отдельные кнопки копируют что-то одно.
3. Сверху — выбор пресета и **«Применить к клипам»**: баннер, теги и подпись пресета накладываются на оригиналы. Новый пресет удаляет файлы предыдущего, поэтому у каждого клипа всегда максимум два варианта: **оригинал** и **последний пресет** (переключатель на карточке). «Убрать пресет» оставляет только оригиналы.
4. Внизу — **«Удалить все клипы и освободить место»**: удаляются оригиналы, варианты с пресетом и ненужные исходные видео.

### Вход в аккаунты TikTok в один клик
Аккаунты добавляются в «Аккаунты» → блок «TikTok-аккаунты» (логин, пароль, заметка). Пароль хранится в базе narez на твоём компьютере в открытом виде и в интерфейс не возвращается.
Чтобы кнопка «Войти» работала в твоём браузере, один раз установи расширение из папки `browser-extension` (Chrome/Edge/Brave: `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение»). При первом «Войти» расширение вводит логин и пароль (капчу и код с почты вводишь сам). При переключении аккаунта оно сохраняет куки уходящего аккаунта и возвращает куки нужного, поэтому TikTok не видит «нового устройства» и не просит код с почты каждый раз. Если сессия устарела — кнопка «С паролем». Сессии лежат в хранилище расширения, как и пароли — открыто. Расширение забирает данные у narez один раз, по клику в интерфейсе.
Вход нескольких аккаунтов с одного IP TikTok может счесть подозрительным; для надёжности используй отдельные профили браузера или разные прокси.

## Нарезка: конец исходника, музыка, режим «Реддит»

- **Отрезать конец исходника** (по умолчанию 15 с, поле в блоке нарезки; 0 — не отрезать): последние секунды видео (титры, музыка, прощание) в клипы не попадают. Для видео короче ~25 с не применяется.
- **Начало клипа.** Фразы-пометки («[Музыка]», ♪, «[Аплодисменты]») выкидываются из транскрипта, модели запрещено начинать с музыки/заставки/приветствия, а начало на пометке или обрывке в одно слово сдвигается на ближайшую настоящую фразу. Музыка, играющая *под* речью, не убирается.
- **«Реддит»** (только режим «Интересные моменты»): границы историй ищутся по картинке — в начале каждой истории на экране появляется карточка поста Reddit (аватар, r/…, заголовок); так начало клипа попадает ровно на начало истории, и это не требует LLM (на видео в ~20 минут занимает около минуты). Если карточек на экране нет, границы ищет модель по тексту, а если и она не нашла — видео режется подряд по концам фраз. Комментарии относятся к предыдущей истории, затем истории склеиваются по 2–3 в клип длиной 60–180 с. Настройки (необязательно, в `config.toml`): `[reddit] min_seconds, max_seconds, stories_per_clip, min_stories, max_clips, visual` (`visual = false` отключает поиск по картинке). Если истории по 100–130 с, две в 180 с не влезают — клип будет из одной истории; чтобы собирать по 2–3, поставь `max_seconds = 300`.

## Стикеры

Вкладка «Пресеты» разделена на «Пресеты баннеров» и «Пресеты стикеров». Стикер — маленькая картинка без фона (PNG/WebP), приклеенная поверх клипа.
- **Положение** — в процентах высоты экрана, 100 % = самая верхняя точка, по умолчанию стикеры случайно расставляются на высоте 50–95 %.
- **Размер** — в миллиметрах на экране телефона (кадр 1080 px ≈ 67 мм): по умолчанию 4 мм, как живой муравей (≈ 64 px).
- **Библиотека** лежит в `assets/stickers` (в проекте уже 12 нарисованных насекомых: муравьи, божья коровка, пчела, жук, муха, комар, таракан, бабочка, стрекоза, гусеница, клоп-солдатик). Свои PNG/WebP с прозрачным фоном загружаются на той же вкладке.
- **Где применяется пресет стикеров:** в «Редакторе» (к клипу или ко всем клипам группы), в «Шаблонах» (у каждой группы свой пресет баннеров и свой пресет стикеров) и во вкладке «TikTok» (можно применить вместе с пресетом баннеров или отдельно). Стикеры накладываются последними, поверх баннеров и видео-вставки.
- Режим «Реддит» теперь не накладывает свои субтитры (они уже есть в исходном видео).
- Настройки по умолчанию (необязательно, `config.toml`): `[stickers] size_mm, y_min, y_max, count, dir`.

### TikTok: выбор клипов, журнал, буфер обмена
- У каждого клипа во вкладке TikTok есть галочка «в выборке»; «Применить к выбранным», «Убрать пресет у выбранных» и «Удалить выбранные» работают только с отмеченными (кнопки «Выбрать все» / «Снять выбор»).
- Внизу вкладки — журнал: наложение баннеров и стикеров, сброс пресетов, удаление клипов, ошибки (дублируется в `workspace/logs/tiktok.log`).
- «Скопировать всё» кладёт в буфер по очереди путь, описание и название (пауза 1,5 с, запись делает сама программа через PowerShell — так в истории Win+V остаются все три). Если у клипа есть изменённая версия (баннер, стикеры, пресет), копируется путь к ней, иначе к оригиналу.

### Браузер для запуска
По умолчанию narez открывается в браузере системы. Чтобы открывать в конкретном (например, там, где стоит расширение для TikTok), добавь в свой `config.toml`:

```toml
[ui]
browser = "chrome"      # chrome, edge, firefox, brave, opera, yandex или полный путь к exe; "" — браузер системы
```

Если в Chrome выполнен вход сразу в несколько Google-аккаунтов (у каждого — свой профиль и свои расширения), выбери профиль, где стоит расширение narez:

```toml
[ui]
browser = "chrome"
profile = "tiktok.acc@gmail.com"   # почта аккаунта, имя профиля или папка («Profile 2»)
```

Посмотреть профили: `python run.py --list-profiles`. Разово: `python run.py --browser edge --profile "Работа"`. Не найден — откроется браузер по умолчанию, в консоль напишет об этом.

### Скорость баннера и длина клипа в TikTok
- В пресете баннеров у видео-баннера есть поле «Скорость ×» (от 1 до 2, по умолчанию 1 — без ускорения): картинка и звук баннера ускоряются, на экране он идёт короче (баннер 4 с при ×2 — 2 с). Для картинок поле не показывается.
- У каждого клипа во вкладке TikTok показана длина «минуты:секунды» (для варианта с пресетом — реальная длина файла, например при паузе на баннере она больше).
