# narez — ссылка → вертикальные клипы (этап 1)

Работает: скачивание (yt-dlp) → речь в текст (faster-whisper) → выбор моментов локальной LLM (Ollama) →
нарезка 30–60 с в 9:16 → субтитры (опц. перевод) → рекламный баннер → группы аккаунтов в SQLite.
Публикация на площадки — этап 2 (сейчас dry-run).

## Установка (Windows)
1. Python 3.11+ (галочка «Add to PATH»)
2. `winget install Gyan.FFmpeg` — перезапусти терминал
3. Ollama: https://ollama.com → `ollama pull qwen2.5:7b` (слабый ПК: `qwen2.5:3b`, поменяй в config.toml)
4. В папке проекта:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

## Запуск
- Веб-версия (основная): двойной клик по `start.bat` (или `python run.py`) — поднимется http://localhost:8000 и откроется браузер. Вкладки: Панель, Редактор, Аккаунты, История; работает и на телефоне (в той же сети пока не открыт — только localhost). При первом запуске `start.bat` сам доставит fastapi/uvicorn.
- Старый GUI (пока оставлен): `python app.py` — создай группу → вставь ссылку → «Нарезать»
- CLI: `python -m narez.cli "https://youtube.com/watch?v=..." --group Собаки`
- Тесты: `pytest`

Клипы лежат в `workspace/clips/jobN/`. Все настройки (модель, длительность, баннер, язык субтитров) — `config.toml`.

## Баннер
`banner.enabled = true`, положи PNG в `assets/banner.png`. Появляется ровно на `start_at`…`start_at+duration`
секунд, не более `max_per_clip` раз.

## Структура
`downloader` → `transcriber` → `moments` (LLM + проверка длительности/границ по фразам) → `subtitles` →
`editor` (ffmpeg) → `pipeline`; `db` (группы/аккаунты/клипы); `publishers/` (заготовка этапа 2).

## Точность субтитров
- Слабая модель Whisper путает сленг и названия. `base` — для быстрых проверок, для результата ставь `small`
  (CPU) или `medium` / `large-v3` (видеокарта NVIDIA).
- `vocabulary` в `[whisper]` — впиши термины и имена из видео; название ролика подставляется автоматически.
- Видеокарта NVIDIA: `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` — программа сама подхватит библиотеки.
  Если не заработает, она сама перейдёт на процессор.
- У каждой модели свой кэш транскрипта, при смене модели видео распознаётся заново.

## YouTube Shorts (публикация)
1. https://console.cloud.google.com → создай проект → «APIs & Services» → включи **YouTube Data API v3**.
2. «OAuth consent screen»: тип External, добавь свой Google-аккаунт в **Test users**.
3. «Credentials» → Create credentials → **OAuth client ID** → тип **Desktop app** → скачай JSON, сохрани как `assets/client_secret.json`.
4. В программе: привяжи к группе аккаунт `youtube` → «Войти в YouTube» → в браузере выбери свой Google-аккаунт и канал.
5. Нажми «Опубликовать». По умолчанию `privacy = "private"` — проверь ролик на канале, потом поставь `public` в `config.toml`.

Задержка: 1-й клип уходит сразу, остальные — отложенно (`delay_minutes` в `[youtube]`), расписание хранит сам YouTube.
Важно: пока Google-проект не прошёл аудит API, YouTube может принудительно оставлять загруженные через API видео
приватными. Чтобы снять ограничение, подай форму аудита: https://support.google.com/youtube/contact/yt_api_form
Квота API: одна загрузка стоит ~1600 из 10 000 единиц в сутки (около 6 видео/день на проект).
Для нескольких каналов в разных группах используй одни и те же OAuth-данные — токен хранится на каждый аккаунт отдельно.

## Редактирование клипов, баннеры, история

- После нарезки клипы остаются в списке «Клипы, ждущие публикации» (список сохраняется между запусками). Двойной клик — окно
  редактирования: название, описание, хэштеги, баннер. «Открыть клип в плеере» — посмотреть клип, «Предпросмотр с баннером» —
  собрать клип с баннером и открыть.
- Баннер — PNG/JPG или видео (mp4/mov/webm). У видео-баннера свой звук: пока он идёт, звук основного видео приглушается до
  `duck_percent` (по умолчанию 15%) и плавно возвращается. Видео-баннер занимает не меньше `min_area_percent` (25%) площади экрана.
  Баннер накладывается отдельным проходом ffmpeg при предпросмотре или публикации, поэтому его можно менять сколько угодно.
  Баннер по умолчанию для всех новых клипов задаётся в `[banner]` в config.toml (`enabled = true`).
- Вкладка «История»: превью (клик — открыть видео на YouTube), название, аккаунт, статус, просмотры/лайки/комментарии.
  «Обновить статистику» делает один запрос `videos.list` (1 единица квоты на 50 видео). Для статистики нужен доступ на чтение:
  один раз нажми «Войти в YouTube» заново (старые токены продолжают работать для загрузки).
- После успешной загрузки клипа во все аккаунты YouTube группы его файлы удаляются; исходное видео и кэш распознавания — когда
  в задании не осталось клипов в очереди (`[cleanup] enabled = false` отключает). Если канал упёрся в дневной лимит загрузок
  (`uploadLimitExceeded`), оставшиеся клипы просто ждут в очереди — нажми «Опубликовать» позже.

## Время публикации и публикация из редактора

- В окне редактирования у клипа есть поле «Время публикации» (формат `07.10.2026 18:30`, время вашего ПК). Кнопка
  «Запланировать на указанное время» загружает клип сразу, а на YouTube он выходит в назначенное время (минимум через 5 минут).
  Кнопка «Опубликовать сейчас» очищает время и выкладывает клип немедленно.
- Время клипа главнее общей задержки `delay_minutes`: клипы без своего времени идут по обычному правилу (первый сразу,
  следующие с задержкой). Если заданное время уже прошло, клип выкладывается сразу.
- Внимание: запланированное видео в назначенное время становится ПУБЛИЧНЫМ независимо от `privacy` в config.toml.
- На главной вкладке: «Опубликовать выбранный клип…» публикует только выделенный клип, «Опубликовать все клипы из списка» — все.


## Этап 2: что добавлено
- **Любые ссылки**: YouTube и ~1000 сайтов, прямые ссылки на файл (.mp4 и т. п.), страницы с плеером, ссылка без `https://`, плейлист (берётся первое видео), путь к видеофайлу на компьютере. Для сайтов, требующих вход: `[download] cookies_from_browser = "chrome"` в config.toml.
- **Папки** (Панель → «Видео из папок»): Исходники / Клипы / Тесты. Исходник → «Нарезать», готовый клип → «В редактор». Пути: `[paths] sources_dir / clips_dir / test_dir` (по умолчанию внутри `workspace`). Автоочистка после публикации удаляет файлы только внутри `workspace`.
- **Тестовый прогон** (галочка на Панели): клипы сохраняются в папку тестов, в редакторе помечены «тест», публикация для них отключена, автоочистка их не трогает.
- **Пресеты** (Редактор): баннер с настройками + теги + текст в конце описания; применить к одному клипу или ко всем клипам группы.
- **Пауза на баннере**: галочка в настройках баннера (или `[banner] pause = true`). Основное видео замирает на кадре, играет баннер (со своим звуком), затем клип продолжается; клип длиннее на время баннера.
- **Прокси** (вкладка): список в любом формате (`ip:port`, `user:pass@ip:port`, `ip:port:user:pass`, `socks5://…`), проверка с показом IP, страны, города и пинга, выбор рабочего прокси. Используется только для скачивания видео; для SOCKS нужен пакет PySocks (есть в requirements).

## Instagram Reels и TikTok

Оба сервиса публикуются через официальные API. Отложенной публикации у них нет, поэтому если у клипа задано время или
задержка, он попадает в **очередь** (страница «История» → «Очередь Instagram и TikTok») и выкладывается автоматически
в назначенное время — **пока narez запущен**. Клипы без времени уходят сразу.

Ключи приложений кладутся в файл `.env` рядом с `run.py` (шаблон — `.env.example`), в `config.toml` их хранить не нужно.

### Instagram (Instagram API with Facebook Login)
1. Аккаунт Instagram должен быть **профессиональным** (Business или Creator) и привязан к Facebook-странице.
2. https://developers.facebook.com → «Мои приложения» → создать приложение (тип Business) → добавить продукт **Instagram**
   (API setup with Facebook login) и **Facebook Login**.
3. Настройки приложения → Основное: скопируй **ID приложения** и **Секрет** в `.env` (`INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`).
4. Facebook Login → Настройки → **Valid OAuth Redirect URIs**: `http://localhost:8765/callback`
   (порт меняется в `config.toml`: `[instagram] redirect_port`).
5. Пока приложение в режиме разработки, публиковать могут только пользователи с ролью в приложении (Роли → добавь себя и
   владельцев аккаунтов администраторами/тестировщиками) — проверка Meta для этого не нужна. Чужие аккаунты — только после App Review
   прав `instagram_content_publish`, `instagram_basic`, `pages_show_list`, `pages_read_engagement`.
6. В narez: аккаунты → Instagram → «Войти» → разреши доступ к странице и Instagram-аккаунту.
Лимит API — 100 публикаций за 24 часа на аккаунт. Видео: Reels до 90 секунд, вертикальное.

### TikTok (Content Posting API)
1. https://developers.tiktok.com → Manage apps → создать приложение; добавить продукты **Login Kit** и **Content Posting API**
   (включи Direct Post), права `user.info.basic`, `video.publish`, `video.upload`.
2. **Redirect URI**: `http://localhost:8766/callback/` (порт — `[tiktok] redirect_port` в `config.toml`).
3. **Client key** и **Client secret** → `.env` (`TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`).
4. Пока приложение не прошло аудит TikTok, все видео публикуются только как «Только я» (SELF_ONLY), а аккаунт должен быть
   добавлен в Sandbox/Target users. После аудита поставь в `config.toml` `[tiktok] privacy = "PUBLIC_TO_EVERYONE"` (это значение по умолчанию —
   если аккаунту разрешено только SELF_ONLY, narez выберет его сам).
5. В narez: аккаунты → TikTok → «Войти».

Дополнительные необязательные настройки в `config.toml` (добавлять нужно только то, что хочешь менять):

```toml
[instagram]
graph_version = "v23.0"
redirect_port = 8765

[tiktok]
privacy = "PUBLIC_TO_EVERYONE"   # PUBLIC_TO_EVERYONE / MUTUAL_FOLLOW_FRIENDS / FOLLOWER_OF_CREATOR / SELF_ONLY
redirect_port = 8766
disable_comment = false
disable_duet = false
disable_stitch = false
```
